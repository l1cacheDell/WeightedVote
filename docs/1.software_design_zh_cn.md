# 第一阶段：HR 的准备 & 分发（无后端，SQLite/文件传递）

身份生成在员工侧，HR 只拿 commitment 和权重。

1. 员工侧（本地）

    - 生成两段秘密：identity_nullifier 与 identity_trapdoor（前端随机数）。
    - 计算 commitment = Poseidon(identity_nullifier, identity_trapdoor)。
    - 把 commitment（16 进制/十进制均可）给 HR。不要把两个秘密给任何人。

备注：权重 weight ∈ {1,3} 由 HR 决定，不是员工自填（演示期可先自填，最终由 HR 覆盖）。

2. HR 侧（本地）
    - 收集名单：若干 (commitment, weight)。
    - 计算每个叶子：leaf = Poseidon(commitment, weight)。
    - 用这些叶子构建 Poseidon-Merkle 树（深度与电路一致，例：20）。

    - 生成并保存：
        - merkleRoot
        - tree.json（各层/或可用于客户端求路径的结构）
        - electionId（即 externalNullifier，本轮唯一 ID）

    - 发布：把 merkleRoot + electionId 上链（或至少前端配置），并把 tree.json 分发给员工（你现在的 MVP 就是 SQLite/文件导入）。

匿名性要点：HR 只有 commitment ↔ weight，看不到员工的链上地址；员工投票时只用零知识证明 + 一次性地址。

# 第二阶段：投票（电路输入/过程/输出）
## 电路公共输入（public inputs）

merkleRoot：HR 发布的本轮根。

externalNullifier：即 electionId，绑定本轮会话。

option：你投的选项编号（公开；MVP 直接用）。

## 电路私有输入（witness）

identity_nullifier（员工秘密）

identity_trapdoor（员工秘密）

weight（你的权重，必须与白名单中的绑定一致）

pathElements[depth]、pathIndices[depth]：从 tree.json 求得的 Merkle 路径（兄弟节点 & 左右指示）

## 电路内部约束（你这版电路的语义）

commitment = Poseidon(identity_nullifier, identity_trapdoor)

leaf = Poseidon(commitment, weight)

用 pathElements/Indices 自底向上哈希，得到 root == merkleRoot

nullifierHash = Poseidon(identity_nullifier, externalNullifier)（公开输出，用于防重复投）

(weight - 1) * (weight - 3) == 0（权重域）

outWeight = weight（公开输出，用于加权计票）

## 电路公开输出（public outputs）

nullifierHash：本轮唯一票据指纹（链上去重）

outWeight：你的权重（MVP 公开；若要隐藏权重，需进阶方案）



# 网页开发架构
## 员工页：处理commitment
目标：本地生成身份秘密 → 计算 commitment → 存到本地 SQLite（仅 commitment），并导出一份“我的身份包”文件给员工自己保存。

**UI**

- [生成密钥] 按钮（随机 identity_nullifier、identity_trapdoor）。

- 显示 commitment（可复制）。

- [保存到本机] 下载 identity.json（只存在用户电脑，不入库）。

**存储**

直接 存储到云端SQLite 表 identities：只写 commitment（不写 nullifier/trapdoor）。

## HR页：准备（Roster + Tree + Election）
目标：把员工 commitment 与 HR 指定 weight 绑定为叶子，构树并产出 merkleRoot / tree.json / electionId。

**步骤**

1. Roster 页：导入 CSV（commitment,weight），或从本机 SQLite 读取员工提交的 commitment，HR 在这里设置/覆盖 weight（1 或 3）。

2. Tree 页：计算：
    1. leaf = Poseidon(commitment, weight)
    2. 构建 Poseidon Merkle（深度与你电路一致，例如 20）
    3. 产出并保存：merkleRoot、tree.json、electionId（可用时间戳/UUID）到 elections 表。

3. Election 页（可选）：如果上链计票，把 root 和 electionId 写入合约；纯本地演示就把它们写进 SQLite/前端 config。

## 员工页：投票页
目标：本地生成 ZK 证明并投票（链上或本地记录）。
过程

由 commitment = Poseidon(nullifier, trapdoor)、weight 找到自己的叶子索引，并从 tree.json 生成 pathElements / pathIndices。

组装 witnessInput（全部十进制字符串）：
```json
{
  identity_nullifier: "...",
  identity_trapdoor:  "...",
  weight: "1" | "3",
  pathElements: [ "...", ... ],    // len=depth
  pathIndices:  [ "0" | "1", ...], // len=depth
  merkleRoot:   "...",
  externalNullifier: "<electionId>",
  option: "<int>"
}
```

groth16.fullProve(input, base+"/zk/weighted_vote.wasm", base+"/zk/circuit_final.zkey") → 得到 {proof, publicSignals}

- publicSignals 含：nullifierHash、outWeight、option、merkleRoot、externalNullifier

计票：

- 链上版：把 proof + publicSignals 调合约 vote()；合约做 verifyProof，用 nullifierHash 去重，累加 tally[option] += outWeight。
- 本地版（无合约）：用 snarkjs.groth16.verify(vk, publicSignals, proof) 本地校验，写入 SQLite 表 votes_local(election_id, nullifier_hash, option, weight)（同时维护去重 map，避免重复提交）。
